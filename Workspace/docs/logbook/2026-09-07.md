### Wrong profile trap (operator correction)

Initial agent setup followed the **native Windows Slicer** path
(`launch-dentoworkflow.ps1`, `DENTOBOT_ROS_PROFILE=none`). That path does not
need Docker/ROS and cannot run Step 6 SlicerROS2. The operator required the
**Windows 11 lab** path documented under SETUP (`install-lab-wsl` /
`launch-lab-workflow`). Do not use the PowerShell native launcher for lab
acceptance.

### Gaps vs prior README / SETUP instructions

These steps or fixes were required beyond a literal README copy-paste:

1. **Distro name.** Bat scripts defaulted to `Ubuntu-24.04`. This PC’s WSL
   distro is `Ubuntu`. Set `DENTOBOT_WSL_DISTRIBUTION=Ubuntu` or use the
   updated bats that default to `Ubuntu`.
2. **`install-lab-wsl.bat` `$HOME` quoting.** Passing `$HOME` through
   `cmd` → `wsl ... bash -lc "..."` emptied the clone path
   (`could not create work tree dir ''`). Prefer
   `wsl -d <distro> --exec bash ...` or run `install-lab-wsl.bash` from a
   WSL login shell after an explicit clone into
   `~/dentobot/ros2_ws/src/DentoBot`.
3. **Fresh clone on `main` vs lab tag.** A clone lands on `main`; the
   installer then refuses maintainer/main worktrees before it can detach to
   `lab/*`. Workaround used: `git fetch --tags` and
   `git checkout --detach refs/tags/lab/2026-09-03`, then rerun
   `install-lab-wsl.bash`.
4. **GHCR auth on old `gh`.** WSL Ubuntu 22.04 packaged `gh` 2.4 has no
   `gh auth token`. Login used the stored oauth token from
   `~/.config/gh/hosts.yml` piped to `docker login ghcr.io` (do not print
   the token). Prefer upgrading `gh` and
   `gh auth login -h github.com -s read:packages`.
5. **No `/dev/dri` on WSLg.** Launcher previously hard-required
   `/dev/dri/renderD128` (Ubuntu Intel pin). WSLg exposes `/dev/dxg` and
   `/mnt/wslg`, not DRM render nodes. Added `DENTOBOT_GRAPHICS_MODE=wslg|auto`
   and `Workspace/compose.wslg.yaml` (`devices: !reset []`, WSLg mounts).
   GUI is functional-only (llvmpipe-class), like CRD.
6. **`xhost` missing.** WSL image lacked `xhost`. Launcher now continues on
   WSLg without `xhost`, defaulting `DISPLAY=:0` when empty.
7. **Docker Desktop `restart --timeout`.** `docker restart --timeout 30`
   fails (`unknown flag`). Use `docker restart -t 30`.
8. **Bind mount hides image `slicer_ros2_module`.** Host
   `ros2_ws` mount replaces the image install tree. First launch must
   `colcon build` `slicer_ros2_module` (and the two DENTOBOT ROS packages)
   inside the container. Launcher now includes that package in its build
   select list. First build took ~4 minutes here.
9. **CPU vs CUDA backend.** Published lab docs pinned CPU/OpenVINO
   (Python 3.12). This Windows GPU machine uses the Bridge C **cu130** pin
   (Python 3.10, `torch==2.10.0+cu130`). Launcher now accepts
   `DENTOBOT_BACKEND_DEVICE=cpu|cuda:0` with separate probes.
10. **GPU inside the container.** Inference runs as the bind-mounted Conda
    interpreter **inside** the container, so CUDA needs NVIDIA device
    requests. Added `Workspace/compose.cuda.yaml` using Compose
    `deploy.resources.reservations.devices` (plain `gpus: all` was rejected
    by this Compose schema). Launcher force-recreates when `cuda:0`.
11. **Editable inference on the lab checkout.** Reinstall
    `pip install --no-deps -e Inference` from the WSL lab tree so
    `--require-device` matches the launcher (older installs only had
    `--require-cuda`).
