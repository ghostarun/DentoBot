### Why this branch exists

A clean laptop setup hit several gaps that the CPU/Intel-only Ubuntu docs did
not spell out:

1. NVIDIA kernel module 550 vs userspace 580 → `nvidia-smi` NVML mismatch until
   conflicting 550 packages were removed and the machine rebooted onto 580.
2. Official Ubuntu launcher refused anything except `cpu` / Python 3.12 CPU
   pins; Bridge C CUDA uses Python 3.10 + `torch==2.10.0+cu130`.
3. Explicit `docker compose -f Workspace/compose.yaml` did **not** auto-load
   overlay `compose.override.yaml`, so `gpus: all` never reached the container
   (`DeviceRequests=null`, no `/dev/nvidia*`, CUDA false inside docker exec).
4. Launcher colcon only built `dentobot_description` + `dentobot_moveit_config`,
   so GUI launch failed with
   `package 'slicer_ros2_module' not found`.
5. `numpy` (and later matplotlib/filelock) had been satisfied from
   `~/.local` on the host; the Conda env bind-mount into the container did not
   include user-site, so metadata probes failed until packages were reinstalled
   with `PYTHONNOUSERSITE=1`.

### Follow-up: torchvision NMS failure (same day)

First `segment-teeth` on `cuda:0` failed with
`RuntimeError: operator torchvision::nms does not exist`. Cause: a generic
`torchvision==0.25.0` wheel was present alongside `torch==2.10.0+cu130`
(pulled transitively by `timm`). Fix: install matching
`torchvision==0.25.0+cu130` from the cu130 index; pin both in
`Inference/requirements/pytorch-cu130.txt` and require the `+cu130` tag in the
launcher CUDA dependency probe. Retry segmentation after the env fix.
