## Step 6A continuation and legacy-package regression reported after the gate

- **Observed:** an older Step 6 `.dentocase` no longer opened. After loading a Step 5 case, the first Step 6A landmark was visible and the status showed `1/4`, but the placement action remained disabled as `Placement active`; the operator could not proceed to Right TMJ.
- **Landmark root cause:** the widget finalized a pending surface-specific point only when it received `PointPositionDefinedEvent`. Valid Slicer Markups interaction paths can first or exclusively notify this observer through `PointModifiedEvent` or `ModifiedEvent`. The defined point and transient pending index then coexisted, permanently disabling the next action.
- **Landmark source fix:** pending-point finalization now depends on MRML state (`pending index < defined point count`) rather than a single event identity. The active-placement action remains available as an explicit recovery control: it finalizes an already-defined pending point or cancels an unfinished placement without forcing deletion of all earlier accepted points.
- **Legacy-package root cause:** schema `1.0` declares lineage extensions optional, but node comparison still compared an older saved record with all metadata emitted by current software. Attributes added by current placement/Step 6 hydration could therefore make intact historical geometry appear mismatched.
- **Legacy-package source fix:** current node/Step 6 metadata is projected to the exact dictionary shape recorded by the schema-V1 package before comparison. Every historically recorded field, point, matrix, mesh count/bounds, volume geometry, list, and value remains strict; only keys absent because they were introduced by newer software are optional. ROS-state exclusion is unchanged.
- **Verification state:** implementation only. No parser, build, package-open, Slicer interaction, or runtime verification was run for these fixes. Per operator direction, the next check requires a new explicit approval after this change summary.
