### Challenges faced (this machine)

1. **Docker Desktop OOM** — `com.docker.backend` ballooned (~49–63 GB private
   RAM) on a 32 GB host → hard reset / Safe Mode. Mitigation: uninstall
   Desktop; run **docker-ce inside WSL**; keep Desktop off; `.wslconfig`
   memory/swap caps.
2. **Wrong defaults vs host** — distro name `Ubuntu` (26.04) not
   `Ubuntu-24.04`; workspace `G:\IITM\Dentobot` not `~/dentobot`; lab bats
   miss the overlay unless env vars are set.
3. **Installer incompleteness** — Conda, TotalSegmentator cache, and a real
   `.dentobot.env` are not created by `install-lab-wsl`; launch fails closed
   until done manually. `--skip-docker` still requires `docker` on PATH.
4. **GHCR / Docker auth** — after Desktop removal, leftover
   `credsStore: desktop` broke pulls until plain auth was restored.
5. **CUDA stack** — Bridge C needs Py 3.10 + cu130 (`dentobot-cuda`); missing
   `pytest` failed the launcher pin probe; container GPU needed
   `nvidia-container-toolkit` (`could not select device driver "nvidia"`).
6. **WSLg GUI visibility** — Slicer reached DENTOWorkflow but window was
   minimized off-screen (`-32000,-32000`) or taskbar-only/blank. Root causes
   included missing `/usr/lib/wsl` in the container, wrong
   `XDG_RUNTIME_DIR`, and OpenGL; fixed with mounts +
   `LIBGL_ALWAYS_SOFTWARE` / llvmpipe / `QT_OPENGL=software`. Black viewports
   remain expected on this path.
7. **Desktop launcher bugs** — cmd.exe mangled bash `${LD_LIBRARY_PATH}` inside
   the `.bat`; fixed by calling `launch-from-windows.sh`. OneDrive Desktop
   (`E:\OneDrive\Desktop`) is the real Desktop on this PC, not
   `C:\Users\tarun\Desktop`.
8. **Noise ≠ conda failure** — Slicer pip-as-root WARNING is Slicer's embedded
   pip; host `dentobot-cuda` was already healthy.

### Lab update channel (day-to-day)

- **Lab PCs update via** `Workspace/scripts/update-lab-release.bat` /
  `update-lab-release.bash`. The updater pins from `LAB_RELEASE`, syncs
  `slicer_ros2_module`, runs `docker pull` **only if the digest changes**, and
  runs **colcon inside the container**. Lab PCs must **not** rebuild
  `Dockerfile.slicerros2`.
- **`publish-lab-image.bash` is maintainer-only**: tag the local
  `COMPOSE_IMAGE` → GHCR `IMAGE`. Lab operators do not run this.
- **WSL distro autodetection** lives in `resolve-wsl-distribution.bat`: prefer
  `Ubuntu`, then `Ubuntu-24.04` / `Ubuntu-22.04` / `Ubuntu-20.04`, else the
  first name from `wsl -l -q`.
- **Commit `5dbd371`**: `LAB_RELEASE` pin to `lab/2026-09-09` (same underlying
  image `20260903` initially). The updater reads `LAB_RELEASE` from
  `origin/main`, then detaches to the annotated lab tag. Compose WSLg path
  includes D3D12/NVIDIA mounts as previously hardened.
- **Chicken/egg problem**: a frozen lab tag's own copy of the updater cannot
  see newer pins that only exist on `origin/main`. **Fix in `27a12f9`**:
  - `DENTOBOT_REPO` override;
  - `run-update-lab-release-from-main.bash`;
  - the `.bat` fetches the helper from `origin/main` into `/tmp/...` then
    runs it (no cmd-hostile `${}` / `$()` embedded in the bat).
- Tag **`lab/2026-09-09`** was force-moved to `27a12f9`, later to `e802513`
  (final pin after the 20260909 image re-label publish).
- **E2E update check**: detached at `lab/2026-09-03` (`760a8ce`) → bootstrap
  from main → landed on `lab/2026-09-09`; full update OK. Colcon was skipped
  when the container `Running=false`.
- **Desktop entry points on Tarun-X1**:
  `E:\OneDrive\Desktop\Update Dentobot Lab.bat` plus
  `resolve-wsl-distribution.bat`.

### GitHub Actions — what we checked (not implemented)

- Repo currently has **no** `.github/workflows` directory / files.
- Manual PAT push is **not** the recommended long-term methodology for
  publishing the lab image.
- Official tutorial:
  https://docs.github.com/en/actions/tutorials/publish-packages/publish-docker-images
- Recommended shape (for a future implementation, not this commit):
  - Job `permissions`: `packages: write` (+ `contents: read`;
    `attestations` / `id-token` when attesting);
  - `docker/login-action` with `GITHUB_TOKEN`;
  - `docker/metadata-action`;
  - `docker/build-push-action`;
  - pin Actions to commit SHAs;
  - optional artifact attestation.
- Local thin re-label was a **pragmatic RAM workaround on Tarun-X1**. Steady-
  state CI should do **real** `Dockerfile.slicerros2` builds on
  GitHub-hosted runners.
