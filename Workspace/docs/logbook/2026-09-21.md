## A. Executive reconstruction

The system does **not** place the robot from a physical mounting edge or face. It
places it from a **two-stage simulation prior**:

1. **Anatomical virtual forehead** — built independently from Case Foundation
   (opened-mouth dental frame + arch scale + glabella offsets), outside CBCT FOV.
2. **Frozen operator capture** — a forehead-relative rigid transform `T_rel`
   captured on 2026-09-18 after the operator manually rotated an unlocked base
   to a visually acceptable pose.

The production propose path is:

```text
T_world_base = T_world_forehead @ T_rel
```

with optional (currently disabled) planar TCP refinement. Manual nudge/lock, not
snap, is the intended correction path. Circular mount-plane snap is quarantined.
Everything is `VisualizationOnly` / `Unregistered`; it does **not** close
physical mount truth (`S6-U-02`).

The six hard-coded values are **not** arbitrary magic numbers — they are a
**deliberate operator-captured canonical simulation seating pose** at URDF-zero
joints, obtained via `forehead_relative_seating()` and frozen into
`VirtualForeheadConfig`.

## C. Coordinate-frame and transform map

### Frame definitions

| Frame | Meaning | Source |
|-------|---------|--------|
| **World / Slicer RAS** | Patient/scene coordinates (mm) | Slicer convention |
| **Dental frame** | Origin = lower incisor; X = patient-right (condyle L→R); Y = anterior; Z = superior (forced +Z in RAS) | `dental_frame_from_landmarks()` L178–195 |
| **Virtual forehead frame** | Origin = glabella estimate; Z = outward forehead normal (reclined from dental anterior); X = patient-right; Y = toward mouth | `propose_virtual_forehead_plane()` L163–180 |
| **Robot base (`base_link`)** | Massless URDF root; fixed −90° X to `link-1` | `dentobot.urdf` L143–148 |
| **Robot link frames** | URDF FK chain from `base_link` | `link_transforms_base_m()` |
| **TCP (`dentobot_drill_tcp`)** | Canonical non-spinning planning TCP at J6=0 | `dentobot.urdf` L214–225 |
| **Jaw transform** | Rigid mandible opening about condylar axis | `step6CaseJawTransform` |
| **CBCT/anatomy** | Source volume/segmentation in world RAS | Untransformed source; moving lower carries jaw transform |

### Forehead axes (verified from code, L173–180)

```text
z_hat = outward forehead normal (extraoral, away from face)
       = normalize(cos(recline)*dental.y_hat + sin(recline)*dental.z_hat)

y_hat = toward mouth (in-plane, patient anterior direction)
x_hat = patient-right (right-handed: cross(y_hat, z_hat), aligned with dental.x_hat)
```

Comment at L173: *"Right-handed: X patient-right, Y toward the mouth, Z outward."*

### URDF `base_link` physical meaning

**CONFIRMED BY DOCUMENTATION/HISTORY:** `base_link` is a **massless integration
root**, not a physical mount datum. The documented physical mounting reference
is **link-1's thin local-Y-normal face**, placed parallel to RViz XY via the
fixed `base_link→link-1` rotation (`dentobot_description/README.md` L28–30;
logbook 2026-08-14 L121–124).

### Production transform equation

```text
T_world_base = T_world_forehead @ T_forehead_base

T_world_forehead = [ x_hat | y_hat | z_hat | origin_mm ]   (4×4, from VirtualForeheadPlane.matrix_world())

T_forehead_base = Rz(0) @ Ry(0) @ Rx(base_rx) ... + [tu, tv, tz]^T
                  (forehead_base_offset_matrix; rotation = Rz@Ry@Rx per _rotation_xyz_deg)
```

With defaults and no slide/yaw:

```text
T_world_base = T_world_forehead @ T_rel
```

where `T_rel` is exactly what `forehead_relative_seating()` extracts:

```text
T_rel = inv(T_world_forehead) @ T_world_base
```

Optional (disabled) refinement:

```text
T_world_base = T_world_forehead @ T_slide @ T_yaw @ T_rel
```

## D. Virtual forehead construction

**Algorithm** (`propose_virtual_forehead_plane`, L149–211):

1. **Inputs:** `DentalFrame`, `arch_scale`, optional CBCT RAS AABB,
   `VirtualForeheadConfig`.
2. **Origin:**
   ```text
   origin = incisor + (glabella_superior_mm * scale) * dental.z_hat
                      - (glabella_posterior_from_incisor_mm * scale) * dental.y_hat
   ```
   Defaults: 90 mm superior, 12 mm posterior (L41–42, L161–163).
3. **Normal:** 18° recline from dental anterior toward superior (L164–168).
4. **In-plane axes:** Gram-Schmidt on dental Z and Y; flip X if misaligned with
   dental right (L169–180).
5. **FOV push:** If CBCT AABB extends above origin along superior, push origin
   outside superior face + 8 mm clearance (L182–185, L214–234).
6. **Proxy patch size:** `patch_width/height/depth` from parameter node (passed
   from UI dimensions).

**Does not use:** robot pose, mount plane, link-1 geometry, or operator base.

## E. Robot seating construction

**Algorithm** (`seat_base_on_forehead`, L237–251):

```python
forehead = plane.matrix_world()          # T_world_forehead
slide[:3,3] = slide_u*x_hat + slide_v*y_hat   # world-aligned in-plane translation
yaw[:3,:3] = Rz(yaw_deg)                 # about fixed/world Z
return forehead @ slide @ yaw @ forehead_base_offset_matrix(config)
```

**At propose time** (`proposeVirtualForeheadAndBase`, L793–813):

- `seat_base_on_forehead(plane, config=config)` — slide=0, yaw=0
- `apply_tcp_slide_on_propose = False` → TCP optimization not applied
- Joints forced to URDF-zero display `(0,0,0,0,0,0)`
- Base authority set to `VirtualForeheadPriorV1`; mount locked = False

**Orientation:** entirely from frozen `base_rx/ry/rz` in `T_rel`, not from
aligning a named robot face to the forehead plane.

**Translation:** `tu/tv/tz` in forehead frame plus forehead origin in world.

## H. TCP slide optimization

### Intent (`slide_base_for_tcp_target`, L273–315)

- **Target:** Opened lower incisor world position (`TCP_AIM_OPENED_LOWER_INCISOR`)
- **Why incisor:** Workspace-centering heuristic — pull q=0 TCP toward opened
  mouth workspace (not mount determination)
- **Why zero joints:** `DEFAULT_JOINT_DISPLAY`; frozen FK during search
- **Method:** Grid search over ±40 mm planar slide (forehead u/v) and ±15° yaw

### Status

**CONFIRMED BY CODE:** `apply_tcp_slide_on_propose: bool = False` (L56). Propose
always uses unslid matrix (L793–803). TCP error reported for diagnostics only
(L795, L860).

### Why disabled

**CONFIRMED BY DOCUMENTATION/HISTORY:**

- Early identity `T_rel` + TCP slide hung robot through FOV (changelog L22–28)
- After operator capture, TCP slide intentionally off — seating is
  mechanical/extraoral via `T_rel`, not incisor aim (changelog L3–8, DECISIONS
  L5897–5898)

### Previously enabled?

**CONFIRMED BY DOCUMENTATION/HISTORY** — Yes, before extraoral fix (changelog
L22–25 mentions TCP-to-incisor slide).

### Transform correctness (slide term)

**Analysis of** `forehead @ slide @ yaw @ T_rel`:

- `slide` uses world vectors `x_hat`, `y_hat` in a pure-translation matrix
- Because `x_hat`, `y_hat` are columns of `R_forehead`, and
  `R_forehead @ (u*x_hat + v*y_hat) = u*x_hat + v*y_hat`, the **base-origin
  slide matches forehead-frame translation `[u,v,0]` when yaw=0**
- `forehead @ slide` does **not** double-apply forehead rotation (S is
  translation-only)
- **Potential issue when yaw≠0:** `yaw` is `Rz` about **world Z**, not forehead
  Z — only matters if `slide_base_for_tcp_target` runs

**Current operational impact:** **None** — slide/yaw always 0 on propose.

### `snapRobotBaseToPlane()` (L1097–1119)

**What it does:**


Copies **plane origin + orthonormalized plane axes directly into base
transform** — i.e. base origin = plane origin, base Z = plane normal.

**CONFIRMED BY TEST** (`slicer_tests.py` L3601–3605): snapped base origin =
plane origin; base Z = plane normal.

origin/orientation to whatever the plane pose is. Does not reference link-1
mounting face.

**Status:** **Quarantined** — UI disabled (`widget_robot_placement.py` L285);
handlers show error (`widget_robot_scene.py` L1325–1333); authority
