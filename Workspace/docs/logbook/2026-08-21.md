## Step 6.3 planning algorithm (implemented 2026-08-18)

Implementation: `DENTOWorkflow/Resources/Python/DENTOStep6Planning.py`. Simulation
only — no MoveIt, no hardware command, no clinical safety claim.

### Pipeline

1. **Context import (6.0):** `validate_planning_context()` requires parameter-node
   roles: `inputVolume`, `teethSegmentation`, `trajectoryLine`,
   `targetDockingAssemblyModel`, `finalPrintableTemplateModel`. Optional roles
   include support models and target bounds ROI. Import sets a flag; framing uses
   `combine_ras_bounds()` over case-view roles (ignores degenerate boxes).

2. **Mount lock (6.1):** Base transform must be locked before 6.3. Robot pose
   comes from locked MRML base matrix or ROS TF under the same parent.

3. **Task limits (6.2):** `default_task_joint_limits_from_urdf()` seeds from URDF;
   operator min/max clamped via `apply_task_joint_limits_to_display_ranges()`.
   Merged UI uses `apply_task_limit_range_to_value()` per joint.

4. **Trajectory sampling:** `sample_trajectory_world_mm()` linearly interpolates
   Entry→Target Markups in world RAS mm (`sample_count` ≥ 2).

5. **Per-waypoint IK:** `_solve_position_ik_display()` minimizes squared
   burr-origin error in base frame with **SciPy `L-BFGS-B`**, seed = previous
   waypoint, bounds = task joint limits. **Position only** — no bur-axis alignment
   to trajectory tangent.

6. **Self-collision:** Reuses `CoarseKinematicModel` from
   `dentobot_description/scripts/manual_joint_state_publisher.py` — non-adjacent
   link AABBs with configurable clearance (default 5 mm). Reports draft overlap,
   not exact mesh or swept volume.

7. **Environment clearance:** Subsampled closed-surface points from teeth
   segmentation, template shell, docking assembly, and support anatomy.
   `evaluate_motion_configuration()` checks minimum point-to-burr-origin distance
   (default clearance parameter). Point cloud, not continuous surface.

8. **Output:** `MotionPlanResult` with joint waypoints, collision indices, burr
   world path. Preview animates MRML link transforms; Plan may reject on first
   failing waypoint.

## 15:45–16:15 IST — ROS/MoveIt repair implementation

### Outcome

Implemented the recommended **surgical repair**, not a whole workflow rewrite.
Kept the verified URDF meshes, MRML base/mount controls, generic phantom/TMJ
opening, task limits, and Step 6 UI. Replaced the brittle ROS control plane and
the ROS-active custom IK path.

### Logic chains implemented

1. **External lifecycle:** the desktop launcher builds and owns
   `simulation.launch.py`; a trap sends SIGINT when Slicer exits. Embedded
   Slicer no longer imports `subprocess`, scans processes, calls the ROS CLI,
   mutates module paths, or starts/stops nodes.
2. **Readiness state machine:** a ROS node samples graph node/service names and
   `/joint_states` publisher endpoints every 0.5 s. It publishes sorted JSON
   (`dentobot.simulation_status.v1`). Readiness is the conjunction of description
   nodes, `move_group`, Cartesian service, and exactly one joint publisher.
   Slicer validates schema, `simulation_only`, and message freshness.
3. **Kinematic contract:** SRDF chain `base_link → dentobot_tool_tcp`; KDL IK;
   OMPL RRTConnect; conservative per-joint simulation velocity/acceleration.
   TCP origin equals the uncalibrated CAD burr origin; a fixed rotation makes
   TCP +Z parallel to the spindle/J6 axis.
4. **Pose construction:** for Entry `e` and Target `t`, compute
   `z=(t-e)/||t-e||`; project a stable world reference axis perpendicular to z;
   normalize x; compute `y=z×x`; recompute `x=y×z`. Linearly sample positions
   and reuse the right-handed basis at every waypoint.
5. **Frame conversion:** phantom/teeth/guide polydata are first hardened to
   world RAS mm, then multiplied by the inverse world matrix of the Step 6 base.
   Hidden proxies are published with frame `base_link`; SlicerROS2 performs the
   ROS coordinate/unit conversion.
6. **Collision logic:** exact URDF visual meshes remain collision meshes;
   adjacent mechanical pairs only are disabled in SRDF; non-adjacent pairs stay
   checked; `default_robot_padding=0.005` supplies the draft 5 mm margin.
   The old AABB/point algorithm remains the MRML-only fallback.
7. **Manual/preview motion:** Step 6 and Motion Control produce a fixed-name
   six-joint SI vector. One external node clamps it to URDF limits and republishes
   `JointState`. Planned named points are reordered explicitly; preview stops on
   the first publish failure instead of displaying a false completion.
8. **Safety boundary:** `allow_trajectory_execution=false`; no controller,
   transmission, `ros2_control`, driver, hardware topic, or execute call exists.

## 16:45–17:38 IST — Economical collision guard and runtime IK proof

### Outcome

Kept the repaired external ROS 2/MoveIt architecture and added one command
validation boundary instead of rewriting the backend. Slicer remains a thin
simulation client; MoveIt remains plan/preview only. No controller, hardware
command, drilling operation, patient data, commit, push, or Drive sync occurred.

### Algorithms and ownership logic

1. Slicer sends a fixed-order six-joint SI candidate to
   `/dentobot/slicer_joint_positions`; it never publishes `/joint_states`.
2. `dentobot_collision_guard` obtains the chain, variables, limits, transforms,
   collision meshes, and SRDF Allowed Collision Matrix from the MoveIt
   RobotModel. It does not duplicate forward kinematics or load an IK solver.
3. The transition from last accepted to requested state is subdivided by
   `ceil(max(|Δq_revolute|/1 deg, |Δq_prismatic|/0.5 mm))`, capped at 1000
   samples. Each linear joint-space sample is updated through RobotState.
4. Every sample must satisfy URDF bounds, exact URDF mesh self/world collision,
   `distanceSelf() >= 0.005 m`, and, when world objects exist,
   `distanceRobot() >= 0.005 m`. FCL is used through MoveIt's PlanningScene;
   only adjacent mechanical pairs are ignored through the SRDF matrix.
5. Acceptance republishes the vector on
   `/dentobot/validated_joint_positions`; the sole external state publisher
   then emits `/joint_states`. Rejection preserves that last accepted vector
   and publishes schema `dentobot.joint_command_status.v1` with reason, body
   pair, distances, sample count, world-object count, requested state, and
   accepted state. Step 6 and Motion Control restore their widgets accordingly.
6. Kinematics are model-driven: URDF supplies joint origin/axis/type/limit;
   SRDF declares `base_link → dentobot_tool_tcp`; `kinematics.yaml` selects the
   KDL numerical Jacobian plugin. `/compute_ik` solves one pose from the current
   seed. `/compute_cartesian_path` samples the Entry→Target TCP line at at most
   0.5 mm, seeds each solve from the preceding waypoint, checks bounds and
   collisions, and returns a completion fraction. No DH table or symbolic IK
   equations are hand-authored. OMPL RRTConnect is available for general plans
   but is not the current straight Cartesian Step 6 algorithm.
7. Locking a placed base republishes current phantom/case/guide collision
   proxies in `base_link`; disconnect publishes removals. The old AABB method
   remains only a coarse no-ROS fallback.
