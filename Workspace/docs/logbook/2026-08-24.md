# Dentobot Logbook — 2026-08-24

## Objective and decision

Implement a reliable save/restore boundary for DENTOBOT cases that include
Slicer geometry and workflow state but interact with external ROS 2, robot
description, TF, and MoveIt runtime objects. The accepted design keeps one
geometry authority: a sanitized MRB inside a versioned `.dentocase` package.
The package adds integrity, lineage, and robot-resource compatibility records;
it never serializes a live ROS graph or treats a restored base transform as an
active connection.

This work directly addresses the reported duplicate
`/dentobot/simulation_status` subscriber, null URDF root, fallback-robot
collision, and reload/new-case failures. No patient identifiers, hardware
motion, drilling, Git publication, or Google Drive synchronization were in
scope.

## Implemented behavior

- **Save:** generate a transient MRB through existing StartSave/EndSave ROS
  sanitization; restore the live scene URL/root/modified state; reject any MRB
  containing ROS2 MRML nodes, the runtime singleton, or the active flag; write
  canonical metadata and streaming SHA-256 hashes; validate a sibling
  temporary archive; atomically replace the destination.
- **Open:** validate paths, member limits, exact inventory, schema, coordinate
  declaration, and hashes before scene mutation; make a recovery MRB; extract
  and clear-load the embedded scene; independently recompute and compare
  workflow records; restore the recovery scene if the post-load comparison
  fails.
- **Coordinate/measurement guard:** compare Markups world-RAS points,
  transform matrices, model mesh counts/bounds, volume dimensions/spacing/
  IJK-to-RAS, segmentation counts, roles, names, classes, and selected
  DENTOBOT attributes with `1e-6` numerical tolerance.
- **Runtime guard:** never restore ROS publishers/subscribers, TF robot,
  MoveIt proxies, runtime default node, or active connection state. Compute a
  portable fingerprint from installed URDF/SRDF/xacro/YAML/STL content and
  block Step 6 import on mismatch. Connection remains explicit.
- **Freshness guard:** package validity cannot promote stale workflow output.
  The supplied Step 5C and Step 6 scenes both retain their real Step 4C/5C
  stale state after round trip.

### Implemented logic and ownership chains

- Added `DENTORobotWorkflowFacade.py`. It is an orchestration boundary rather
  than a second kinematics implementation. Inputs are operator degrees/mm and
  Slicer world-RAS/mm; `DENTORobotPlacement` and `DENTOROS2Bridge` retain
  radian/metre and frame conversion. Every action returns immutable
  `success`, `code`, `message`, `details`, and optional payload data. Joint
  requests first validate finite task-limit values, write the parameter node,
  submit to the collision-gated adapter, and roll back to the last accepted SI
  state on rejection. Base updates invalidate the cached plan and planning-
  scene flag. Preview advances named joint vectors with a Qt timer and stops on
  any rejected waypoint. There is deliberately no Execute/hardware method.
- Kept IK model-driven: the façade asks the configured generic Motion Control
  adapter to solve `base_link → dentobot_tool_tcp` through MoveIt's KDL plugin.
  It does not calculate DH parameters or symbolic inverse equations. The most
  recent successful IK vector becomes the MoveIt joint-goal plan input.
- Kept collision authority split and labelled. ROS-active candidates pass
  through the external MoveIt PlanningScene/FCL transition guard with 1 degree
  / 0.5 mm interpolation and 5 mm clearance. The deterministic six-dimensional
  Halton sequence, URDF FK, link AABBs, and subsampled TCP/environment distance
  remain a fast approximate workspace visualization only.
- Routed Legacy Step 6 connect/disconnect, local load, manual joints, base
  lock/unlock, workspace generation, Entry-to-Target planning, preview, and
  Stop through the façade. Existing MRML nodes and the typed parameter node
  remain the only case state.
- Added `DENTOApplicationShell.py`. It maps internal stages 0–10 onto Case,
  Imaging, Segmentation, Drill Planning, Guide Design, and Robot Simulation;
  reparents the one authoritative module widget between the stock module panel
  and a task dock; and never copies controls or geometry. `QSettings` stores
  only mode, theme, Expert mode, and dock geometry. Focus mode snapshots and
  restores each Slicer chrome widget. Cleanup restores the widget, removes both
  docks, and disconnects shell presentation state.
- Added `DENTORobotSimulationPanel.py` as presentation-only code. Its six task
  substeps show runtime capability, existing base placement, existing manual
  joints, TCP Goal/IK, PlanningScene/FCL status, and plan/preview. The custom
  panel imports Qt only and invokes callbacks supplied by the workflow; it
  contains no ROS query, URDF parse, kinematic calculation, or collision math.
- Added semantic light/dark QSS resources and an action-parity inventory.
  Legacy is still the fail-closed default and can be restored at runtime.
