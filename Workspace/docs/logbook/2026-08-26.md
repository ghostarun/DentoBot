## Step 5B insertion-direction false stale state after package load

- Operator evidence: package open succeeded, but Step 5C verification was
  disabled and later reported patient-shell/final-template failures with stale
  reason `The template insertion direction changed`, even after rebuilding from
  Step 4B.
- Static package evidence: the retained
  `SampleStudy1/dentobot-case-step6.dentocase` records no freshness issue at
  save. Its insertion line is two world-RAS points
  `[-74.88598980214555, -66.70089742021065, 52.049150466918945]` and
  `[-74.47031887612044, -65.6323406015914, 67.782846366723]`; those values
  exactly equal the embedded patient-shell `InsertionGeometryJson`. The shell
  and final template are `Current`, and saved final verification is `WARNING`
  with no `FAIL`. Rebuilding geometry was therefore not a valid remedy.
- Root cause: `_onTemplateInsertionDirectionModified` treated every generic
  line `ModifiedEvent` as a geometry edit. After package commit, application
  stage ownership reapplied lock/selectability; summary refresh could also set
  labels. Either non-geometric event cascaded stale state through undercut,
  patient shell, and final template after the loader's post-bind audit.
- Fix:
  - cache insertion-line point count/status and defined world-RAS coordinates
    when binding;
  - ignore insertion events during the package barrier and ignore subsequent
    metadata/reference/label/display/lock/selectability events when geometry is
    unchanged at `1e-6 mm`;
  - retain normal downstream invalidation for a real Approach/Seat edit;
  - restore missing schema-v1 selectability for the generated insertion axis as
    intrinsically read-only, rather than applying the generic selectable
    fallback;
  - enhance both exact-package and full package smoke scripts to compare the
    insertion line with shell provenance, require Current shell/final state,
    and run final geometry verification without any failure.
- Verification:
  - compile passed with the task-specific pycache under `/tmp`;
  - `pytest -q Testing` returned `99 passed`; `git diff --check` passed;
  - focused Slicer test printed `DENTOBOT_INSERTION_EVENT_FILTER_PASS` after
    proving attribute/label/lock/selectability events cause zero invalidations
    and a `0.01 mm` Seat edit causes exactly one;
  - enhanced exact-package regression opened the operator package twice,
