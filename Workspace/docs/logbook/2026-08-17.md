### 15:22 IST — Step 6 implementation

- Added local BodyParts3D loading, four ordered TMJ/incisor landmarks, a
  deterministic pure-hinge solver, visible achieved-gap line, reset/delete
  actions, and parameter-node persistence. Reused the existing forehead mount
  plane, snap/flip, local base nudge, keyboard, and six manual joint controls.
- Kept the three public STL files and screenshots outside Git/Drive. Recorded
  source attribution, CC BY-SA 2.1 Japan license, normalized filenames, and
  SHA-256 values in setup documentation.

Programming/geometry logic chain:

1. **Asset resolution and reuse:** search `DENTOBOT_PHANTOM_ROOT`, the
   container workspace-data bind, the configured workspace root, then module
   ancestors for the three normalized filenames. Load STL coordinates
   explicitly as Slicer RAS millimetres, reject empty polydata, and reuse nodes
   by stable `DENTOBOT.ModelRole`/`PhantomPart` attributes rather than names.
   Skull/maxilla stay untransformed; only the mandible may have the jaw
   transform parent.
2. **Landmark contract:** create one unlocked four-point Markups fiducial node
   with a maximum of four control points. Interpret indices strictly as left
   TMJ, right TMJ, upper central incisor, and lower central incisor; require all
   four finite world-RAS points before solving. Names shown in Slicer are
   presentation, while role attributes provide persistent identity.
3. **Pure hinge matrix:** normalize `rightTMJ - leftTMJ` as the world-space
   hinge axis and use the midpoint of the two TMJ points as pivot. Build the
   3x3 axis-angle rotation with Rodrigues' formula, then set homogeneous
   translation to `pivot - R*pivot`. This fixes every point on the hinge axis
   and applies no independent jaw translation or scale/shear.
4. **40 mm gap solve:** sample both opening directions from -60 to +60 degrees
   on a deterministic 0.05-degree grid because landmark handedness is manual.
   Transform the closed lower-incisor point for each candidate, measure its
   Euclidean distance to the fixed upper-incisor point, minimize absolute
   target error, and use the smaller absolute angle as the tie-break. Persist
   requested gap, achieved gap, and hinge angle on the transform.
5. **MRML output/persistence:** parent the mandible below the jaw
   `vtkMRMLLinearTransformNode`; create a locked two-point Markups line from
   fixed upper incisor to transformed lower incisor; bind model, landmark,
   transform, line, and 40 mm parameter through the scripted parameter node.
   Reset writes identity/removes the measurement, while delete removes only
   nodes carrying the disposable Step 6 roles.
6. **Robot forward geometry:** convert UI degrees/millimetres to URDF
   radians/metres, parse the acyclic joint tree, and accumulate each child as
   `parent * joint-origin * axis-motion`. Enforce package-local mesh URIs and
   the tracked STL scale, convert transform translations back to Slicer
   millimetres, then parent seven link-pose transforms below one editable
   robot-base transform. The photographed q=0 offsets, -90° integration-root
   base orientation, and negative J4 axis are already encoded in the tracked
   URDF; positive displayed J4 therefore propagates mainly toward base -X.
7. **Forehead placement:** derive the base pose from the Markups plane by
   normalizing its Z normal, projecting/normalizing an in-plane X axis, and
   computing right-handed `Y = Z cross X`; preserve the plane origin and
   remove scale/shear. Fine translation/rotation post-multiplies a rigid local
   delta (`base * delta`), so arrows/buttons follow the placed base axes.
   Keyboard shortcuts are opt-in, active only in Step 6, and ignored while a
   text/numeric editor owns focus.
8. **Display behavior:** the workflow's stage presets can hide unrelated scene
   content, so the Step 6 update explicitly restores visibility for owned
   robot/phantom models and relevant Markups only while Step 6 is active. This
   fixed the blank first graphical capture without weakening other stages'
   visibility rules.
9. **Existing 5 mm advisory:** the earlier RViz/manual tool transforms every
   collision mesh's local min/max corners at the current joint pose, encloses
   them in base-frame axis-aligned boxes, skips direct parent/child pairs, and
   computes nonnegative per-axis separation followed by Euclidean distance.
   Non-adjacent pairs below 5 mm are colored/warned but never block motion.
   Because rotated AABBs and visual-derived collision meshes are coarse, this
   trial does not treat the warning as mesh, swept, head, mouth, cable, mount,
   or safety collision checking; Slicer currently supplies no additional
   phantom-contact gate.
