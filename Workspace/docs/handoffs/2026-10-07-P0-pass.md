## 4. Step B: S6-FRAME-SYNC-01, the coordinate-sync verification layer (main work)

**Why:** an audit read lower-jaw geometry without its parent transform and produced false collision alarms for
three teeth, while the bounds-only scene check passed. This is image-guided-intervention software: frame agreement
must be proven by **independent layers**, at mesh level, at every decision point.

**Existing assets (reuse, don't rewrite):**

| Asset | What it does |
|---|---|
| `Testing/step6_frame_audit.py` | Checks A–D: scene bounds, kinematics (own URDF FK vs KDL vs MoveIt FK), task, collision. Plus `exact_mesh_separation`, `mesh_surface_deviation` and `model_world_polydata`. |
| `Testing/moveit_scene_dump.py` | Out-of-Slicer rclpy oracle. Dumps MoveIt's world meshes, ACM, padding/scale, robot_description identity and `/check_state_validity`. |
| `Testing/step6_audit_d_compare.py` | MoveIt mesh vs Slicer mesh (both directions), ACM verdict, exact separation, one classified finding. |
| `dentobot_workflow/jaw_frame.py` | Owning-jaw frame helpers. |
| Production | `DENTOROS2Bridge.read_moveit_world_object_bounds()` (native, bounds only); `base_diagnosis.compare_moveit_scene` (Diagnose row 0, bounds within 0.05 mm); `facade.ensureMoveItSceneMatches()` (the Plan gate). |

Implement the six layers in this order (each is a separate commit).

**L1: one world-geometry accessor + guard test**
- **What:** a single function that returns any model or segment geometry in world RAS with **all parent
  transforms applied**. Every audit and diagnostic reads geometry through it.
- **Where:** create `dentobot_workflow/frame_sync.py`, a production module (VTK allowed, no widget code). Move
  `model_world_polydata` there, plus a `segment_world_polydata(segmentationNode, segmentId)` that applies the
  segmentation's parent transform. Use the same logic as `logic_robot_scene_sync._segmentationSegmentsSurfaceWorld`
  and reuse it if possible. `Testing/step6_frame_audit.py` then imports from `frame_sync`, keeping a thin
  re-export so the existing tests don't break.
- **Guard test** (`Testing/test_frame_sync_guard.py`): an AST scan of `Testing/step6_*audit*.py`,
  `Testing/step6_feasibility_advisor_runner.py` and `dentobot_workflow/base_diagnosis.py` (plus any new
  audit/diagnostic module). Fail on any `<expr>.GetPolyData()` whose receiver is a parented planning node
  (`finalPrintableTemplateModel`, `targetDockingAssemblyModel`, `patientContactShellModel`, the jaw models)
  unless the call is the argument of `model_world_polydata`. Keep an explicit allowlist for intentional jaw-local
  reads, e.g. `OrderedAdvisorRunner._template_poly_jaw_local`, each with a comment saying why.
- **Done when:** the guard test passes, the existing frame-audit tests pass, and no behaviour changes.

**L2: mesh-level scene fidelity (replaces bounds-only)**
- **What:** for **every** MoveIt world object, compare MoveIt's mesh with the geometry Slicer published:
  vertex/triangle counts, bounds, centroid, and two-way surface distance (p95, max).
  - Pass: Hausdorff ≤ 0.05 mm (observed today: 5e-6 to 8e-6 mm).
  - Object id mapping comes from `logic.collisionSceneAuditRecord(node).object_records`
    (`outgoing_collision_object_id`, `source_id`). Check A in `run_frame_audit` already walks this mapping;
    reuse its source-resolution branches (model node, segment, mouth barrier). The bug class lives exactly there.
- **How, phase 1 (do now, no native change):** a Testing-level runtime check.
  1. Generalize `step6_audit_d_compare.analyse` into `analyse_scene(dump_dir, slicer_export_dir)` that loops all
     objects.
  2. Add a Slicer-side exporter: in the runner or a new `Testing/step6_frame_sync_export.py`, write each source
     object's world mesh through the L1 accessor, mapped world→base_link with the inverse Base matrix, as `.npz`
     (vertices and triangles; `.npz` because host VTK 9.1 cannot read Slicer `.vtp`).
  3. Compare against `moveit_scene_dump.py` output.
- **Performance:** `mesh_surface_deviation` currently loops `vtkCellLocator.FindClosestPoint` in Python. That is
  fine for one template (about 40k vertices, seconds), but the scene has about 34 objects including jaws of about
  94k vertices.
  - For L2 use a vectorized path: `scipy.spatial.cKDTree` on a dense surface sample (vertices plus triangle
    centroids) as a **screen**, then exact point-to-triangle distance (`_closest_point_triangle`, already
    vectorized in numpy) only for points whose KD distance exceeds 0.02 mm.
  - Alternatively, `vtkDistancePolyDataFilter` inside Slicer (C++-vectorized).
  - Keep the exact path for the final verdict. Target: under 60 s for the full scene.
- **Phase 2 (operator decision; do NOT start):** a native digest method in `slicer_ros2_module`
  (`GetMoveItWorldObjectMeshDigest`) so Diagnose row 0 can check mesh-level fidelity inside the module. It needs a
  C++ change, a rebuild and the `build.slicer_ros2_if_changed` check. Write the design as an OPEN-QUESTION only.
- **Done when:**
  - pure tests cover synthetic scenes: identical → pass; one object shifted 0.3 mm → fail naming that object;
    a decimated mesh with identical bounds → fail (the exact case bounds-only missed);
  - the runtime script is ready but not run.

**L3: known-answer tests**

  - **Pure:** extend `Testing/test_jaw_frame.py` and `test_step6_jaw_stale.py` patterns:

### Rules for new GUI-button scripts that mimic real user testing

1. **Drive only production controls, the way a user does.**
   - Find widgets by `objectName`. Give every new button one, e.g. `DENTOBOTStep6SaveBranchConfigButton`,
     `DENTOBOTStep6RestoreBranchConfigButton`, and for the advisor `DENTOBOTStep6FindWorkingConfigButton`.
   - Check `visible` and `enabled` before each click. **If a button the user needs is disabled, that is a test
     failure**: record its `toolTip`/status-label reason. It is a real-user dead end (backlog `S6-GUI-HARNESS-GAP`:
     earlier runs passed while users were blocked).
   - Never call logic/facade methods to "help" a step along. Read them only for assertions.
2. **Navigate like the user.** Change the stage via `widget.ui.workflowStageComboBox` and the substep via
   `widget._step6SubstepComboBox`, or reuse `_enter_substep`. Respect `ACTION_OWNER_SUBSTEP`: a click from the
   wrong substep is silently blocked by design.
3. **Modal dialogs are part of the user experience.**
   - Install a QTimer watcher that records every visible `QMessageBox` (title, text, buttons).
   - **Expected** prompts (e.g. "Restore branch Step 6 configuration") are answered with the scripted answer: click
     the specific button (Yes/No) by role.
   - **Unexpected** prompts fail the run with their text. No blanket `accept()`.
4. **Wait on observable state, not sleeps.** Pump `slicer.app.processEvents()` until a label text, enabled state or
   facade/registry state changes, with a bounded timeout per step. Record the elapsed time per step: this feeds the
   performance backlog (`S6-PREVIEW-PERF`).
5. **Assert both layers.** Check the user-visible outcome (label text, enabled buttons, spinbox values, table rows)
   **and** the authoritative state (eligibility reason, registry, facade policy, parameter node, ROS
   connected/not). A pass needs both.
6. **Capture.** Take a screenshot at every stage boundary (`capture_callback`, as in the probes). Acceptance runs
   use `record_slicer_screen.py`. Write a `probe.json` with the step list, timings, modal log, button invocations
   and assertion results.
7. **Isolation.**
   - Work on a case **copy** inside the run directory. Save only to new paths inside the run directory (save/reopen
     tests).
   - Never overwrite source cases. One Slicer at a time. Stop the stack by PID at the end; never restart
     automatically.
8. **Fail closed.** The first failed assertion stops the probe, with all evidence so far. Never retry a click
   "just in case".
9. **Source-contract test for every probe** (pure, like `Testing/test_step6_complete_cycle_probe.py`):
   - the probe never calls planner/preview/restore APIs directly;
   - it uses the documented objectNames;
   - it has no blanket modal dismissal;
   - it is ASCII-only if it runs through the session driver.

  `syncDentoCaseTrajectoryRegistry(legacyProvenance=True)`, then runs a normal sync.
